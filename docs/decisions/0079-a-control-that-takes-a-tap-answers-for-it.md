# 0079 · 一个控件接了这一下，就要为它负责

## Status

Accepted 2026-09-23. S77a，客户端单侧。不新增路由，93 条路由清单不变；
本单只改钱包、行情、价格提醒与全屏 K 线。契约方面只用到已冻结的
`loop-api/docs/frontend-v2-wallet-intents-api.md` §6、§7.1、§7.1.1 与
`frontend-v2-wallet-api.md` 的余额读；`spentUsd` / `remainingUsd` 是 S77b
在 §7.1.1 新增的两个标量槽位，客户端按同一条白名单读法接住。

## Decision

### 1. 一个控件接了这一下，就要为它负责

三个「点了没反应」的控件其实都调了 `LoopToast`——一条 2.6 秒、贴在页面底边的
提示。对一个**长期**不可用的入口，这是错的答案形状：它可能已经被负载拖过去了，
也可能正好被手指挡住，而用户下一秒还会再点一次。

- 钱包「跨链」不再是灰块加 toast，它**打开 `/wallet/bridge`**。那一页本来就是
  为「没有 provider」准备的：从 / 到两个破折号、禁用的「开始跨链」、
  `BRIDGE_RUNTIME_DEFERRED` 的说明卡。原型里 `wallet` 的跨链也是去这一页。
- 钱包列表「添加」打开一张**留在屏幕上的 sheet**：「暂不支持绑定第二个钱包」，
  说明 LOOP 给每个账号建一个 Privy 嵌入式钱包、外部钱包绑定还没有开放，
  以及开放之后已绑定钱包的持仓都计入算力。
- 交易记录「导出」**真的导出**。见 §4。

### 2. Send 的三步，每一步只回答自己的问题

**第 1 步由资产页回答。** `asset` 页的「发送」直接带着 `SendDraft`（钱包 id、
不透明 assetId、symbol）推 `/wallet/send/to`。它已经知道是哪个资产了，再让人
从 11 行里挑出刚刚打开的那一行是多余的。链上余额读失败的行不能带 draft——没有
spendable 就没有东西给金额做校验——那种情况仍然回到第 1 步。

**第 2 步在键盘面前让位。** `LoopFocusPage` 增加 `folioCollapsed`，与
`LoopStreamPage` 同一套做法：折叠是 `SizedBox.shrink()` 换进同一个
`KeyedSubtree`，**不是** `folio: null`。把 folio 置空会改变 Column 每个槽位里
的孩子，下面的输入框会在键盘弹出的那一帧被换到元素树的新位置、丢掉焦点——
S72 在 `community-members` 上已经付过这个代价（R3-3）。

**灰按钮说出差什么。** 固定在底部的「下一步」旁边多一行：地址没填、地址没校验、
数量没填、数量超过可动用，四句各说各的。

**两张警告折成一行。** 收款方的三项检查（首次收款、合约地址、筛查不可用）与
出处说明进一张 `LoopDisclosure`，摘要写「地址核对 · N 项待确认 · 第一条」。
折叠不等于藏：条数就在摘要里。**合约收款方默认展开**——那一条可以让整笔钱回不来。

**出处说明不印库表名。** 「首次收款方的判断依据：你自己在 LOOP 已索引的
ERC-20 转账记录」。`indexed_erc20_transfers` 是一张表的名字，不是给人看的证据。

**确认页先列出它要确认的东西。** hero 承诺「收款方、网络费与到账数量全部确认后
才请求签名」，然后 403 一来，页面上什么都没有。现在 intent 还没到手时，页面先
列出这台设备自己握着的两行（收款方、数量）＋两行还没有的（网络费、预估到账），
并明说「这两行是你在上一步填的内容，还不是服务端的事实」。intent 到手后这张卡
让位给 `MoneyIntentReviewCard`（它与签名弹层同源），另加一行「预估到账 · 不预估」。

原型那里写的是「约 30 秒」。合约里没有任何一个读给出到账时间，用出块间隔在客户端
算一个，是 LOOP 对着别人的钱编了一个数。这一行说自己没有来源，并指向结果页的确认数。

### 3. 策略拒绝按 reasonCode 分开说

`MoneyPolicyRule` 从 6 个常量补到 8 个，补上
`COUNTERPARTY_NOT_IN_CANARY_ALLOWLIST` 与 `CANARY_DAILY_CEILING_EXCEEDED`——
服务端一直在发，客户端读不出来，于是全都掉进兜底句。

| reasonCode | 说的是 |
| --- | --- |
| `COUNTERPARTY_NOT_IN_CANARY_ALLOWLIST` | 收款地址不在允许的收款名单里 |
| `CANARY_CEILING_EXCEEDED` | 超过单笔金额上限 |
| `CANARY_DAILY_CEILING_EXCEEDED` | 会超过 24 小时累计上限 |
| `ASSET_NOT_IN_CANARY_ALLOWLIST` | 资产不在可操作范围里 |

三条上限规则才可以印 `exposureUsd` / `ceilingUsd`；日上限另有
`spentUsd` / `remainingUsd`（「24 小时内已用 $20 · 还剩 $5」），两个都到齐才印——
只有「已用」没有「还剩」不成其为额度。`LoopFailureDetails` 按同一条白名单读法
新增这两个槽位，未列出的 key 依旧到不了页面。

兜底句改成「当前策略不允许这笔操作，没有提交任何交易。这里不猜是哪一条。」
旧句子里的「自定义上限还没有开放」在**任何**一条拒绝里都不再出现：那是一个用户
从来没设过的限额，拿它解释白名单拒绝是答非所问。S77b 之后再加规则，未知 code
走这句中性话，而不是最近的一条。

### 4. 交易记录：导出与详情

「导出」把**当前分段正在列的那些行**编成 CSV，交给系统分享面板。它不偷偷多取几页：
一个悄悄比屏幕上多的导出，是用这一页的形状回答了另一个问题。端口
`WalletActivityExportSink` 放在 feature 里、适配器 `SharePlus` 放在
`lib/integrations/sharing/`，与 `ChatMergeExportSink` 同一套；
`lib/features/` 里不出现插件。CSV 里每个数字都是服务端原样的字符串或 `Decimal`，
不分组、不四舍五入——CSV 是给别的软件读的。文件带 UTF-8 BOM，否则表格软件会按
本地代码页打开一整行中文表头。分段本身没有行（原生转账 / 跨链），导出不生成只有
表头的文件，直接说「这一段没有记录可以导出」。

交易行点开一张详情 sheet：完整哈希可选可复制、BscScan 地址可复制，外加方向、数量、
对方、网络、区块、状态、观察时间。**它不是 `tx-result`**：`tx-result` 报的是这台
设备准备过的一个 intent 并轮询它的状态，而一条索引到的转账没有 intent——它可能
早于这个账号，也可能是在别处签的。

跳浏览器没有做：`url_launcher` 只是传递依赖，直接用它要改 `pubspec.yaml` 与
lockfile，属于依赖决策。sheet 把链接给出来并说明「LOOP 目前不能直接唤起外部浏览器」，
没有承诺一个做不到的跳转。

### 5. 兑换页说清楚「还没选」和「读不到」

`_sourceAssetId` 初始是 `null`，于是「读不到可用余额」在还没选资产时就印出来了——
而一步之外的钱包页正显示着 2.99 USDT。现在四种情况四句话：没选资产、余额还没读到、
钱包没有这一行、以及行本身 unavailable（印服务端的 reasonCode）。选了就读
`balances` 的 `spendableBalance`，与钱包页同源。

三个滑点档进一行等宽分段控件，标签从 `50 bps` 改成 `0.5%`。bps 是交易台的行话；
对着选它的人说不出任何东西。换算在 `Decimal` 上做，精确，去尾零。签名弹层的
「滑点上限」也跟着改——展示的是同一个字段的同一个值，payload 不受影响。

`evidence` 待确认的提示只留一句：标题原先把正文的那句 reasonCode 文案又说了一遍。

### 6. 提醒：资产有名字，条件有语义，删除要问一次

- 资产行显示 token logo + symbol + 名称，**不可编辑**。CAIP id 是不透明标识符，
  它不是名字，用户核不了它，往里打字只能得到另一个资产或一个非法值。已有提醒的
  资产是事实（合约没有「换个资产」这回事），新建时可以从自选里选。
- 四个条件进一行分段控件，下面一句解释选中的那个：「到达：价格达到或高于阈值
  （≥ 阈值）就触发」「突破：价格必须高于阈值（> 阈值）才触发，正好等于阈值不算」。
  四个词差一个字，控件本身说不清楚，就让句子说。
- 「删除这个提醒」从「保存」正下方的整宽按钮改成居中文字按钮，并先问一次。
- 从代币页铃铛进来只显示这个资产的提醒（触发历史同步收窄），下面留一个
  「查看全部资产的提醒」。narrowed 的列表必须说自己 narrowed，否则看起来像丢了行。

### 7. 全屏 K 线就是那张图

图表高度改成「这一页还剩多少就用多少」（屏幕高 − 安全区 − 340pt 页面其余部分，
下限 200pt），竖屏横屏都成立。EMA / MACD / RSI 三个灰按钮和它们的不可用卡片
**整个删掉**：没有实现、也没有人在做，一个为不存在的功能留的灰控件读起来是
「这个按钮坏了」。页面自己的说明写清楚它算哪两个指标、从哪来、以及没有别的。

`scripts/check_harness.py` 的 C3 锁同步改口径：原先锁
`chart-full-indicators-unavailable` 与两次 `MARKET_CHART_TOOLS_DEFERRED`，
现在锁那句「没有其他指标」，并禁止 `'EMA'` / `'MACD'` / `'RSI'` 三个字面量回来。

### 8. K 线数字按量级取位

`loopFormatCandlePrice`（`loop_candle_chart.dart`）：≥1000 两位小数、≥1 四位、
<1 从第一个有效数字起四位有效数字。一条规则配八位小数，在 ETH 上打出
`O 2,759.67162123`——十一位数字，后六位是噪音，而且长到换行；在 1e-6 的
launchpad 池上，两位小数会把价格印成 `0.00`。千分位仍由 `loopFormatDecimal` 给，
全程 `Decimal`，不碰 `double`。

## Consequences

- 钱包首页的「跨链」从禁用态变成可点：它打开的仍然是一个整页 unavailable，
  没有任何地方多出一条可执行路径。
- `LoopFocusPage` 多一个可选参数 `folioCollapsed`，默认 `false`；
  其余 focus 页行为不变。
- `pumpS5Page` 多一个可选 `exportSink`，只有按「导出」的测试装配它；
  生产路径缺适配器时导出是 `unavailable`，不回退。
- `LoopChainException` / `LoopFailureDetails` 多两个只读标量；除日上限外无人读。
- 未做：交易详情的 BscScan **跳转**（要 `url_launcher` 直依赖，需主代理批依赖决策）；
  「预估到账」需要后端给到账口径才能变成数字。
