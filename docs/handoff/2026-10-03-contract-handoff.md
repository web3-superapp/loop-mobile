# LOOP 合约需求交接（2026-10-03）

本文件交给合约、后端和产品共同对齐。它整理《LOOP项目产品计划.docx》及本次产品确认，记录新需求与 Flutter `6639279` 基线的差异；本次只更新交接，不部署、修改或声称完成这些合约。产品已确认的数字与仍需确认的执行定义分开列出，待定内容不能由客户端猜测。

## 1. 确认规则与版本边界

本次确认优先于产品计划中冲突的旧文字：内盘买卖双向税为 **10%**，外盘买卖双向税为 **2%**；文档表格中的“内盘税收2%”不采用。NFT 募集资金毕业后买入该 MEME，再发送到项目方指定的 CZ 地址，按项目的产品定义称为处置/销毁；这不能直接表述为 token `totalSupply` 已减少。能人工执行的流程优先采用人工方案。

| 项目 | 已确认产品规则 | 仍须技术/项目方定义 |
|---|---|---|
| 网络与计价 | BNB Chain/BSC 产品方向，USD1 认购、报价与核心流动性 | 测试网/主网 chainId、正式 USD1 地址/精度、授权资产与执行钱包 |
| 新 MEME 频率 | 每周最多 1 个，非每周必发 | 自然周或滚动 7 天、时区、取消/失败是否占配额 |

| 发射轮次 | **NFT 白名单 → LOOP 质押优先 → 公开轮** | 每轮时间窗、额度、个人限额、剩余额度承接、资格快照和跨轮重复参与 |

| 毕业阈值 | 市值达到 300,000 美元 | 总供应或流通供应口径、USD1/USD 参考价、税前/税后价格、触发确认数与异常处理 |
| 外盘税 | 买入 2%，卖出 2% | 池/路由兼容性、非池转账是否征税、税收权限与税收钱包 |
| 毕业池 | PancakeSwap；V2/V3 待定 | 池型、手续费档、V3 价格区间、初始价格/数量、滑点、建池与注资执行者 |
| LP 处理 | 锁定或处置方案待定 | V2 LP token 与 V3 position NFT 的区别、锁多久、锁仓合约、到期取回、手续费收取与解锁权限 |
| 合约地址品牌 | MEME token 合约尾号统一 `6666` | 工厂/CREATE2 部署方法、完整地址预先验收、实现字节码/初始化参数验证；尾号不是安全证明 |

门槛按原文“超过”处理：整数计数时 5,000 用户或 3,000 NFT 均不满足条件；5,001 / 3,001 才越过对应门槛。NFT 总限量必须大于 3,000 才可能达成发射门槛，但具体上限尚未确认。增长是否跨项目累计、NFT 门槛是否仅当前项目，需在正式版本明确，不能因本表表达而偷偷改变统计范围。

## 2. 共识勋章 NFT

每个 MEME 发射前公开限量铸造，一枚价格 **100 USD1**。两项权益为该项目内盘 NFT 白名单凭证，以及参与 LOOP 共识矿池。NFT 标准、是否可转让、单人铸造上限、名额消耗/复用、质押或仅持有方式、历史项目 NFT 是否继续挖矿，以及权重如何计算尚待确认。

资金流按项目分账：该项目 NFT 收到的 USD1 → 毕业后分期买入该项目 MEME → 将实际到账 MEME 转到指定 CZ 地址。原计划提出合约自动线性买入，本次明确可人工的流程优先人工；自动定时/自动执行并非当前交付承诺。建议先确认总预算、起止时间、分期频率、每期额度、滑点、最低到账量、允许池和执行权限，由运营按批准计划执行并逐笔对账。人工执行不能替代 NFT 铸造、用户交易或领取时用户本人的授权，也不能越过合约限制。

**地址与语义待定：** 项目方须提供 CZ 地址的完整链上地址、chainId、用途说明与批准记录；不得从昵称、新闻或示例地址推导。转到指定地址只证明一笔转账；只有合约确实执行销毁且链上供应记录减少，才能显示“供应量减少”。转入地址是否可再次转出、是否等同不可恢复处置，须另外确认。

**必须对齐的异常：** NFT 未达门槛、项目取消/延期/发射失败时资金退回还是保留；毕业后一直没有可执行流动性时如何等待；买入失败/部分完成/剩余 USD1 如何分账；买入已确认而转出失败时如何只补转出；NFT 因退款或作废被排除时如何撤销资格和算力。客户端不能把购买 NFT 等同于保证发射、保证收益或已经取得代币。

## 3. LOOP 发行与两个矿池

| 项目 | 确认值 | 数学推导（非已部署读数） |
|---|---|---|
| LOOP 总发行量 | 1,000,000,000 枚 | 10 亿枚 |
| 初始流动性 | 总量 10% | 100,000,000 枚 |
| 挖矿总预算 | 总量 90% | 900,000,000 枚 |
| 挖矿周期 | 900 天线性分配 | 若均匀按完整日释放，则总计 1,000,000 枚/日 |
| 共识矿池 | 挖矿预算 50% | 总计 450,000,000 枚；上述按日假设下 500,000 枚/日 |
| 算力矿池 | 挖矿预算 50% | 总计 450,000,000 枚；上述按日假设下 500,000 枚/日 |

900 天起点、整日/秒级释放、暂停是否延长、无合格参与人时余额留存还是递延、舍入余量和最后一日清算须定义。两个池分别记账，不能把其中一池预算重复用于另一池，也不能将 NFT 募集款、Launch 募集款、税费或 LP 本金混作挖矿奖励。

算力矿池基础公式已确认：

`单项资产算力 = 合格持仓数量 × 参考价格 × 该资产权重`

`个人基础算力 = 各项合格资产算力之和`

合格社区资产须加入平台白名单，权重范围 0.1×–1.0×；LOOP 基础权重 1.0×。USD1、LOOP 与平台 Launch MEME 属于计划纳入方向，最终仍需发布 canonical assetId 与有效权重，不能按 ticker 自动纳入。尚需定义：快照块、价格来源/时点/异常价保护、持仓归属、跨钱包绑定、多社区归属与去重、LP/质押持仓是否计入、闪电借贷/短时搬仓处理，以及推荐/邀请加成的计算顺序和上限。

共识矿池不能直接套用算力矿池公式。需给出每项目/每枚 NFT 权重、有效持有人快照、旧 NFT 的持续期限、是否必须锁定、转移后的切换时点及 NFT 跨项目去重规则。产品尚未确认这些参数。

**建议结算协议，待技术确认：** 预充值奖励池、按独立日 Epoch 生成额度账本与可验证领取证明；若采用 Merkle 方案，声明 root 发布/纠错窗口、叶子字段、重复领取防护、过期规则和纠错追偿。若采用人工发放，仍须有唯一结算记录、用户应得/已发/未发额度和链上逐笔对账。当前文件不选定合约实现或默认任何领取机制已存在。

## 4. 现有客户端与新要求的差异

核对源码的事实限定于 `6639279` 基线，不代表后端、合约部署或真机已验收。

| 现有接缝 | 源码事实 | 新需求如何处理 |
|---|---|---|
| Launch 状态与交易 | 已有四轴链上状态、同块读数、购买 intent、广播报告、领取/退款相关模型与适配器 | 保留已审核授权/签名/对账边界；新经济模型需独立版本、ABI 与执行许可 |
| Eligibility | 当前 mode 为 `whitelist/community/activity/unavailable`，解析器要求 `dependsOnStaking=false` | NFT 资格与 LOOP 质押优先需要后端 evaluator、schema、合约共同升级；不能先改标签冒充资格 |
| LOOP stake | `LaunchStake.stake` 为 unavailable，`executable=false` | 质押金额、锁期、等级门槛、退回/解押队列与历史资格快照未接入 |
| Mining | 已有公式版本、持仓算力快照、用户/社区榜单、推荐规则只读模型 | 既有 development baseline 读数不能当成本文件两个产品矿池的收益 |
| Mining rewards | 可领/累计/source 为 unavailable，`claimExecutable=false` | 本次没有上线奖励池、累计账本或领取交易 |
| Graduation | 当前 enum 明确有 `V3_LIVE/LP_LOCKED/COMPLETED`，已毕业投影依赖锁定证据 | 若选 V2 或 LP 处置须明确升级状态与证据；不能将“建池成功”自动标成“LP 已锁定” |
| NFT | 现有 Launch gateway 未提供专用 NFT 铸造/资金处置协议 | 需补充 NFT 读取、铸造意图、资格投影、资金预算与处置记录，当前保持不可执行 |

协议职责建议继续独立：Launch 管销售/募集/退款/毕业；NFT 管铸造与资格凭证；Staking 管 LOOP 锁定/解押和优先轮证据；Mining 管奖励预算/结算/领取。相互读取版本化证据，不混合账本或共用资金余额。Staking 与 Mining 分开，质押只提供资格时不默认另有 APR/APY。部署是否独立、资产托管和管理员角色最终由技术方案确认；资格耦合不等于资金可互相挪用。

## 5. 参数发布与状态要求（开发建议，待协议定稿）

参数发布需要不可变版本，至少携带 `parameterVersion`、适用 chainId/项目/协议地址、ABI/实现版本、批准人、批准时间、生效时间或生效块、内容摘要及前版本。这是交接建议的字段，不是已存在 API。当前客户端已有 `configVersion` 与快照块证据；新协议应说明映射与兼容范围，不复用旧版本字符串承载不同经济模型。待批准版本只读展示为待确认，历史交易保留当时版本。

资格快照固定项目、轮次、规则版本、快照块/时间、NFT 持有/锁定证据或 LOOP 质押证据、额度/有效期与原因码。是否逐轮刷新、跨轮复用和开售后变更规则需锁定；历史资格不得因当前持仓变化被客户端重算。NFT 轮、质押轮与公开轮分别验证，公开轮也仍受时间窗、地址上限、余额/授权和合约暂停限制。

保留 Launch 现有销售/权益/流动性/运营四轴，不用“开售/毕业”一条文字掩盖退款或暂停。NFT 铸造建议独立 `未开售/可铸造/已售罄/暂停/关闭/退款中/已退款`；资金处置建议独立 `待批准/待执行/买入已提交/买入确认/转出已提交/完成/结果未明/需人工复核`；Mining 结算建议独立 `草稿/已批准/已发布/可领取/关闭/纠错`。新状态和 transitions 均为待定协议，不在本次直接添加到应用。

## 6. 人工操作、幂等与对账

人工执行的每项资金操作绑定唯一 operationId，固定 chainId、项目、预算账本、期次、批准版本、执行地址、输入/输出资产、数量、收款地址、滑点和有效期；执行人、批准人及实际 txHash/区块/事件完整入账。建议审批与执行分权，权限、保管方式和暂停负责人待确认。手机只接受获授权的用户意图；管理密钥不能进入 Flutter、fixture、文档或日志。

1. 同一“项目 + 预算 + 期次 + 动作”只能有一项有效操作。内容改变必须撤销旧批准并生成新操作；金额不允许按 UI 浮点数重算。
2. 广播不等于确认。超时、丢回包或无法解码记为结果未明，先查询原操作、交易回执、事件及余额，不创建第二笔买入或转账。
3. 部分完成分别记录：买入确认后只能补送尚未转出的余额，不能再次购买完整预算。替换交易、失败与链重组要记录同一操作的尝试关系。
4. 逐期勾稽：初始 USD1 + 已收资金 − 已买入 USD1 − 已退款/批准费用 = 剩余 USD1；买入到账 MEME − 已发送 MEME = 待处置 MEME。手续费、税、实际到账和未花预算单独列项。
5. LP 注资、LP token/position NFT 归属、锁仓/处置回执与到期权限单独对账。税费回流、NFT 买入与挖矿奖励不能共享一个“已完成”标记。
6. 新用户门槛可先由后台人工审核并发布签名/批准证据，合约是否依赖 oracle、签名授权或只读运营门控需明确。客户端本地计数不能放行发行。

## 7. 开发验收与上线阻断项

必须验收：5,000/5,001 用户和 3,000/3,001 NFT 边界；每周额度与延期；三轮未开放/刚过期/资格转移/重复参与；0.5% 上限的买入、转账及豁免；买卖税前税后实际到账；300,000 美元毕业口径；毕业失败只重试未完成步骤；NFT 买入完成但转出失败的恢复；账户与项目隔离；900 天释放、空 Epoch、舍入尾差、双池预算合计；重复领取与 root 纠错；人工重复点击、丢响应、替换交易和重组后对账。

以下内容确认前 UI 只展示审核通过的规则及待确认项，不开放新增 NFT mint、LOOP stake、两个矿池 claim 或人工执行入口：

- 项目方：最终 chainId/完整资产与 CZ 地址；NFT 总限量、退款政策、共识矿池权益；增长和周配额口径；税费/空投去向及比例；V2/V3、LP 处理和锁期。
- 合约方：曲线、计税及池兼容性、0.5% 限制、权限/暂停/升级、质押/解押、两矿池结算与领取；可审查 ABI、字节码和部署地址证据。
- 后端/运营：地址注册表、参数版本与快照、资格 evaluator、资金审批/执行钱包权限、幂等 operation ledger、索引确认数/重组策略及对账。
- 发布方：独立测试网验收与安全/发布决策。此产品交接不更改现有 Development/Testnet 限制，也不是主网、真实支付或自动交易开放许可。
