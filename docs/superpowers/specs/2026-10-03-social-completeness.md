# LOOP 社交基础体验完善

依据：用户 2026-10-03 要求参考 DeBox 布局和社交功能，先适配 LOOP 现有代码。

## 本轮设计

保留已接受的黑白卡片与 Lime 品牌色（行情另用涨绿跌红）。聊天是第一入口；顶栏只保留搜索与 +，+ 收纳添加好友、创建群组、创建社区、扫一扫、我的二维码。头像打开同一公开资料面板：身份在上，好友/私聊操作在中，公开资产与交易按可见性呈现，管理操作收纳到底部。消息动作在长按菜单；合并海报从消息选择工具栏进入，避免挤占会话标题栏。

沿用系统字体，标题 18–22，正文 15–16，辅助文字 12–13，交互区域至少 48。海报采用白底黑字、LOOP 标识、清晰消息分隔、底部社区二维码；二维码只有公开社区地址或本人公开 ID，不放私聊 CID 或钱包地址。

## 交付边界和验收

1. 复用已有好友申请、follow、block、Stream 消息操作，不把 follow 当成 friendship，不把本地隐藏当成服务端删除。
2. 个人/社区二维码共用已有本地 QR 编码器；扫描结果只识别 LOOP 用户与社区，不执行外部链接或钱包动作。相机扫描缺少平台适配时保留粘贴识别，不模拟扫描成功。
3. 合并长图保留现有匿名安全投影；自愿附加的社区二维码来自调用方已读取的社区 ID，私聊不输出邀请二维码。
4. 头像只用服务端公开资料映射。群消息的 Stream ID 不能自行转换为 publicProfileId；缺少映射的头像不能伪装成可管理好友。
5. 公开持仓/交易、群友买入提示必须有查看者范围、可见性授权、已确认交易来源；生产缺少接口时不显示虚构金额。Preview 可使用独立 fixtures 展示布局，不能写入 Stream。
6. 删除好友需服务端解除双向关系/私聊权限；没有该接口时不发送臆造请求。
7. 验证：二维码解析边界、拉黑成功/失败、自身操作隐藏、消息选择与转发权限、海报包含二维码且不泄露私聊身份，320/390 宽度及文字缩放。

## 已知代码基础

`socialGatewayProvider` 已有请求、关注和拉黑。`ChatForwardController` 已有 Stream 源会话查询、逐条转发、最多 50 条合并图及系统分享。消息 avatar callbacks 被旧身份保护规则全部关闭。个人已有 ID 文本分享但未发现 QR 页面。`friend_gateway.dart` 无删除命令；公开资料仅四字段。无相机 QR 解码依赖。上述差距不代表后端已交付。

## 评审后确认的真实基线

GitHub `web3-superapp/loop-api`，`integration/v2`，`83f5ac7a9de654d28a0628f38a79db44a0c6221b`。默认 main 仍是旧迁移骨架，不能用它判断当前实现。integration/v2 可核实多人提交，包括 muxiaodeng、CWD1208、Doog-bot534。

本轮接通已有能力：DM 公开 peer 头像、V2 好友申请与拉黑、用户/社区本地二维码及 PNG 分享、长按进入文本消息选择、底部合并海报、可取消附带社区 QR。二维码使用 exact LOOP ID / `loop://community/{id}`；只解析 allowlist，社区加入仍经原权限流程。相机识别本轮没有平台适配器，粘贴识别只是替代入口，不计作已交付扫码。自定义社区码也不计作已验证的系统相机 App Link。

后端核验缺口：解除好友被 000013 的 friendships_immutable trigger 主动禁止；群 Persona 未公开 publicProfileId 映射；公开持仓/买卖无 viewer-scoped endpoint；群友买入无 opt-in 事件 producer。相关 owner wallet activity 是转账，不能当买入。上述 4 项必须先扩展后端契约、迁移和隐私验收，本轮不得宣称完整交付。

消息操作规格：长按保留官方复制、回复、删除权限，增加转发/多选；重新按 CID 和当前成员身份查询，以所按消息为初始选项；历史消息需要按 ID 定位读取；底栏固定取消/合并海报，逐条发送选择已加入的目标会话；QR 来源只接受原社区上下文 extra，私聊不提供二维码。
